# nerva-actions v1 — the action language

> **Provenance.** The original prose spec was not in the repository. This document was rebuilt from the executable
> version, `overlay/tools/nerva_actions.py`, which is authoritative: if the two ever disagree, the code wins.
> The tag table below is generated by `python3 overlay/tools/nerva_actions.py tags` and checked against it by
> `overlay/tests/test_actions.py`. Sections 3, 5 and 7 are the ones `nerva_bridge.py` refers to by number.

A model drives the NERVA overlay by writing **actions**: XML-like tags, one command each. The overlay never sees free
text. `nerva_actions.py` parses, validates (`lint`), compiles to overlay stdin lines, and renders the observation the model
reads next. `Session` runs a model turn against a real `nerva-overlay` process.

## 1. Turn shape

- A turn is a sequence of actions and nothing else: **no text outside tags**, no nesting, no unclosed or unknown tags.
- At most **8** executable actions per turn (`<think>` does not count). An empty turn is invalid.
- At most one `<done>`, and it must be the **last** action of the turn.
- Pixel coordinates are **integers**. Body units are **metres** with at most **2 decimals**. Numbers beyond ±100000 are rejected.
- Limits: `<think>` ≤ 400 characters, `<say>` ≤ 300 (and non-empty), `<done>` reason ≤ 200, `<find>` query ≤ 120.
- An invalid turn is **not executed**: the model gets an `<obs>` whose single result is `err invalid turn: ...` with the first three reasons.

## 2. Tags

<!-- TAGS:BEGIN -->
```
flow     <think>        free reasoning, never executed (keep it short)
flow     <say>          text for the user (no effect on the desktop)
flow     <wait>         seconds 0.1-10
flow     <done>         end the task; optional reason
body     <hand>         left|right x y z   |   left|right rest        (metres)
body     <foot>         left|right x y z [yaw_deg]                    (metres)
body     <pelvis>       x y z   |   auto
body     <face>         x z   |   auto
body     <look>         x y z   |   auto
body     <torso>        x y z   |   auto
body     <grip>         left|right 0..1
body     <stand>        (no arguments)
body     <balance>      assist|none
map      <w2px>         x y z   -> screen pixels
map      <px2w>         px py   -> metres (z, y)
pointer  <move>         px py
pointer  <tohand>       left|right   (to where that fingertip is drawn)
pointer  <click>        px py   (move, then left click)   |   (empty = click where the pointer is)
pointer  <rclick>       px py   |   (empty)   -- needs --allow-right-click
pointer  <scroll>       n   |   px py n      (n: -5..5, positive = up)
pointer  <pointer_status> (no arguments)
see      <perceive>     (no arguments)  windows, pointer grant, body
see      <status>       (no arguments)  body state
see      <tree>         [target] [depth 1-30]   UI elements of a window
see      <read>         [target]   the text on screen
see      <find>         words [in target]   elements by name/text, with where to click
see      <focused>      [target]   the element with keyboard focus
see      <apps>         (no arguments)  which windows can be read
```
<!-- TAGS:END -->

Groups: `flow` controls the episode, `body` drives the humanoid (physics and balance are the body's job, the model supplies
coordinates), `map` converts between metres and screen pixels, `pointer` is the AI mouse, `see` reads the screen.

Notes per group:

- **body** — World: Y up, metres; at yaw 0 the body faces +Z and its left is +X. See `docs/BODY.md`. Refusals come back with numbers (for example "step too long (1.24 m, max 0.90 m)").
- **map** — the view is a side view: `screen_x = W/2 + z*ppm`, `screen_y = H - y*ppm`. `<w2px>` / `<px2w>` convert.
- **pointer** — needs the overlay started with `--mouse` **and** a window granted by the human. `<click px py>` is a move followed by a left click; the harness paces moves and clicks so the overlay's rate limits (4 clicks/s, speed cap) are not what fails. `<rclick>` also needs `--allow-right-click`. Scroll takes 1–5 notches, positive = up.
- **see** — reading uses accessibility (AT-SPI) and needs `--a11y`. `target` is `focused`, `granted`, `all`, a window address, or part of a window class.

## 3. Humans only

These exist in the overlay but are **not actions**. A model that writes one gets the turn rejected, with a reason:

| Tag | Why |
|---|---|
| `<grant>` | only the user can grant the pointer (ask with `<say>`) |
| `<revoke>` | only the user can revoke |
| `<hide>`, `<unhide>` | only the user decides what is hidden |
| `<key>`, `<type>`, `<keypress>` | the pointer has no keyboard |
| `<drag>` | dragging is not supported |

Grants and the hide-list come only from the overlay's control socket (`nerva-overlay --ctl ...`), never from stdin.

## 4. Observations

After each turn the harness replies with an `<obs>` block:

```
<obs>
<r>1 ok ...</r>        one result per executed action, numbered by position (think excluded)
<r>2 err ...</r>       err = the overlay or the body refused it, with the reason
<ev>...</ev>           asynchronous overlay events (for example a planted foot)
</obs>
```

- `say`, `wait` and `done` produce no result line; every other action does.
- Multi-line results (tree / read / find / focused / apps) are emitted as `<screen>`, `<text>`, `<found>`, `<focused>`, `<apps>` blocks after the `<r>` line.
- Trees are capped at 60 elements, finds at 12 hits, text at 40 lines.
- Password fields and text fields named like secrets are shown as `(secret)` with no content. Hidden apps appear as `(hidden)` and are unreadable.
- `<perceive>` returns a `<state>` block (screen size, pixels per metre, body, pointer grant, windows).

## 5. System prompt (for a fine-tuned model)

```
nerva-actions v1. You control a small character and, when the user allows it, the mouse of one window.
Reply with actions only: <think>, <say>, <wait>, <done>, body (<hand> <foot> <pelvis> <face> <look> <torso> <grip> <stand> <balance>), <w2px> <px2w>,
pointer (<move> <tohand> <click> <rclick> <scroll> <pointer_status>), and reading (<perceive> <status> <tree> <read> <find> <focused> <apps>).
Pixels are integers, body units are metres. Read before you click. Never type, never read passwords, never touch hidden apps. Finish with <done>.
```

`nerva_bridge.py` carries this text verbatim as `NERVA_SYSTEM`; `--system FILE` overrides it.

## 6. Special tokens

Register these as single **special tokens** in the model's tokenizer so they never get split inside normal text:
every tag in section 2 (open and close), plus the observation tags `task state obs r ev screen text found focused apps`.
`python3 overlay/tools/nerva_actions.py tokens` prints the exact list.

## 7. Training data (episodes)

One JSON object per line (`overlay/tools/examples/episodes.jsonl`, 9 episodes recorded from the real overlay):

```
{"id": "click-001", "v": 1, "task": "...", "start": "<state>...</state>",
  "turns": [{"role": "assistant", "content": "<think>..</think><find>save</find>"},
            {"role": "observation", "content": "<obs>...</obs>"},
            {"role": "assistant", "content": "<click>838 351</click><done>clicked</done>"}]}
```

- Turns alternate assistant / observation, start and end with the assistant, and the last turn ends with `<done>`.
- Rendered for SFT as chat messages: the first user message is `<task>..</task>` followed by `start`; assistant turns stay assistant; observations become user messages. **Loss only on assistant turns.**
- Validate before training: `python3 overlay/tools/nerva_actions.py lint episodes.jsonl` (exit code 1 on any invalid assistant turn).
- Prompt-only first (system prompt + a few episodes as few-shot), fine-tune later: `nerva_bridge.py --fewshot ... --fewshot-ids ...`.
